How the BVH Accelerates Ray Tracing

What an AABB and a BVH actually are, and the specific mechanism — not just the name — by which wrapping a scene in one turns ray intersection from "check everything" into "check almost nothing."

1. An AABB is just two corner points

An axis-aligned bounding box is the tightest box around an object whose faces never tilt — always parallel to the x/y/z axes. aabb.h stores exactly that: one min/max interval per axis.

Testing a ray against a box means testing it against three pairs of parallel planes (slabs) — one pair per axis — and intersecting the three resulting ranges.

2. A BVH nests boxes inside boxes

Group nearby objects, box the group, then group the groups — recursively, until one root box encloses the whole scene. bvh_node builds this bottom-up by splitting the longest axis in half each time. The same tree drawn two ways: where the boxes actually sit, and how they nest as data.

3. Why walking the tree beats scanning the list

Same 5-object scene, same ray. Left: hittable_list tests every object, whether the ray is anywhere near it or not. Right: bvh_node::hit() tests a box first — and an entire missed subtree is skipped without ever running the real per-object math.

6.24× faster
This project's own --benchmark mode, same 487-sphere scene, 300×168 image, 32 samples/pixel, depth 8: linear scan 8.51s → BVH 1.36s. Turning intersection from O(N) into roughly O(log N) is the single biggest performance lever in the whole renderer.
